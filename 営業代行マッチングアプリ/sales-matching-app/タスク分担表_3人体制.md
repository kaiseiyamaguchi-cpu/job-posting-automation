## 🔄 作業の進め方

### Phase 1の並行作業（初日: 4-6時間）

```
時間軸:
0:00 ┌─ 担当者A: Server Actions実装（4.5h）
     │  └─ profile → agency → matching → message → dashboard
     │
     ├─ 担当者B: UIコンポーネント実装（5.5h）
     │  └─ layout → auth forms → profile forms → agency → matching → message → stats
     │
     └─ 担当者C: まず認証ページのみ先行実装（1h）
        └─ login/register ページ（モック使用）

4:00 ─ 担当者C: Aが完了したActionsから順次統合開始（4.5h）
        └─ profile → dashboard → agencies → matching-requests → messages
```

### Phase 2の並行作業（2日目: 3-4時間）

```
時間軸:
0:00 ┌─ 担当者A: 管理者API実装（2.25h）
     ├─ 担当者B: 管理者UI実装（2.25h）
     └─ 担当者C: ドキュメント整備・レスポンシブ確認（2h）

2:30 ─ 担当者C: 管理者ページ統合（2.5h）
```

### Phase 3の最終調整（3日目: 2-3時間）

全員で分担してテスト・デプロイ

## 🚨 競合を避けるためのルール

### 1. Gitブランチ戦略

```bash
# 各担当者は自分のブランチで作業
git checkout -b feature/担当者A-actions
git checkout -b feature/担当者B-components
git checkout -b feature/担当者C-pages
```

### 2. コミット前の確認

```bash
# プルリクエスト前に必ず最新のmainをマージ
git checkout main
git pull origin main
git checkout feature/your-branch
git merge main
```

### 3. 作業ディレクトリの厳守

| 担当者 | 作業可能ディレクトリ | 作業禁止ディレクトリ |
|--------|-----------------|------------------|
| A | `lib/actions/`, `lib/utils/` | `components/`, `app/**/page.tsx` |
| B | `components/` | `lib/actions/`, `app/**/page.tsx` |
| C | `app/**/page.tsx`, `app/**/layout.tsx` | `components/ui/`, `lib/actions/` |

### 4. 共通ファイルの編集

以下のファイルは**担当者C**が一括管理：
- `types/index.ts`
- `middleware.ts`
- `app/layout.tsx`
- `lib/auth.ts`
