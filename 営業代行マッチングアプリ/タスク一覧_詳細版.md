## 💰 Phase 3-A: 案件募集〜応募〜日程調整〜アポ確定/支払い(モック)〜承諾 + お金の流れ可視化（提案デモ用）

### 目的（デモで見せたいこと）
- **業務フロー**: 案件募集 → 応募（「こんな人紹介できる」）→ 採用/チャット → 日程調整 → アポ確定 → 支払い（モック）→ 実施報告 → 企業承諾
- **お金の流れ**: 企業支払総額／鬼カナ取り分／営業代行支払予定（80/20）を、取引詳細と管理者一覧で表示
- **前提**: 決済/48h自動確定/証拠提出など“面倒な部分”は**モック**でOK（監査ログは不要）

### 担当者A（DB・API・状態遷移）
- [ ] **3A.0** 既存DB整合性修正（ID/外部キー/RLSの前提統一）
  - `matching_requests.company_id/agency_id` の参照先を統一（users.id か profiles.id かを決めて揃える）
  - 影響範囲: 外部キー、RLS、ダッシュボード集計、APIのJOIN

- [ ] **3A.1** 新規テーブル追加（提案デモ最小）
  - `job_posts`（案件募集）
  - `applications`（応募：提案文/紹介可能像）
  - `schedule_requests`（日程候補→確定）
  - `appointments`（取引＝お金の流れを束ねる）
  - `payments`（モック決済：unpaid/paid/refunded）

- [ ] **3A.2** RLS/権限制御（新規テーブル分）
  - 企業: 自社案件/自社応募/自社取引のみ閲覧・操作
  - 営業代行: 自分の応募/自分の取引のみ閲覧・操作
  - 管理者: 全件閲覧・（デモ用）強制更新

- [ ] **3A.3** API実装（モック前提）
  - `POST/GET/PUT /api/job-posts`（作成・一覧・更新/公開/終了）
  - `POST/GET/PUT /api/applications`（応募・一覧・採用/却下）
  - `POST/GET/PUT /api/schedules`（候補提示・確定）
  - `POST/GET /api/appointments`（日程確定時に取引作成、金額80/20計算）
  - `POST /api/appointments/[id]/pay`（モック支払い完了）
  - `POST /api/appointments/[id]/complete`（実施報告）
  - `POST /api/appointments/[id]/accept`（企業承諾）
  - `GET /api/admin/money`（管理者用：金額集計・一覧）
  - `POST /api/admin/appointments/[id]/force-status`（デモ用：状態強制変更）

### 担当者B（UIコンポーネント・見せ方）
- [ ] **3A.4** 取引（アポ）詳細の「お金の流れ」表示コンポーネント
  - 企業支払総額、鬼カナ取り分、営業代行支払予定（80/20）
  - 支払い/承諾/支払予定のステータス（未/済）をバッジ表示

- [ ] **3A.5** 管理者「マネー一覧」UI
  - 一覧: 企業/営業代行/支払総額/手数料/支払予定/状態
  - 合計: 総流通額、鬼カナ売上見込み、支払予定残高

### 担当者C（ページ実装・導線・統合）
- [ ] **3A.6** 企業側ページ
  - `/(dashboard)/job-posts`（案件一覧/作成/編集/公開）
  - `/(dashboard)/job-posts/[id]`（詳細 + 応募一覧/採用）
  - `/(dashboard)/appointments`（取引一覧）
  - `/(dashboard)/appointments/[id]`（取引詳細 + お金の流れ + モック操作）

- [ ] **3A.7** 営業代行側ページ
  - `/(dashboard)/jobs`（案件検索/閲覧）
  - `/(dashboard)/applications`（自分の応募一覧）
  - `/(dashboard)/appointments`（取引一覧/詳細）

- [ ] **3A.8** 日程調整UI（メッセージから遷移・または取引詳細内で完結）
