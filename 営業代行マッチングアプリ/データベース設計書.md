## 📋 テーブル定義

### 1. profiles（ユーザー基本情報）

| カラム名 | 型 | 制約 | 説明 |
|----------|-----|------|------|
| id | UUID | PK, FK → auth.users | ユーザーID |
| email | TEXT | NOT NULL | メールアドレス |
| user_type | TEXT | NOT NULL, CHECK | ユーザー種別（company/sales_agency/admin） |
| created_at | TIMESTAMPTZ | NOT NULL, DEFAULT NOW() | 作成日時 |
| updated_at | TIMESTAMPTZ | NOT NULL, DEFAULT NOW() | 更新日時 |

**インデックス:**
- PRIMARY KEY (id)
- INDEX (user_type)

**RLS:**
- ユーザーは自分のプロフィールのみ閲覧・更新可能
- 管理者は全て閲覧可能

| created_at | TIMESTAMPTZ | NOT NULL, DEFAULT NOW() | 作成日時 |
| updated_at | TIMESTAMPTZ | NOT NULL, DEFAULT NOW() | 更新日時 |

**インデックス:**
- PRIMARY KEY (id)
- UNIQUE (user_id)
- INDEX (industry)

**RLS:**
- 企業は自分のデータのみ閲覧・更新可能

### 3. sales_agencies（営業代行プロフィール）

| カラム名 | 型 | 制約 | 説明 |
|----------|-----|------|------|
| id | UUID | PK, DEFAULT gen_random_uuid() | 営業代行ID |
| user_id | UUID | FK → profiles(id), UNIQUE | ユーザーID |
| name | TEXT | NOT NULL | 名前 |
| specialties | TEXT[] | DEFAULT '{}' | 得意分野（配列） |
| areas | TEXT[] | DEFAULT '{}' | 対応エリア（配列） |
| description | TEXT | | 自己PR |
| phone | TEXT | | 電話番号 |
| created_at | TIMESTAMPTZ | NOT NULL, DEFAULT NOW() | 作成日時 |
| updated_at | TIMESTAMPTZ | NOT NULL, DEFAULT NOW() | 更新日時 |

**インデックス:**
- PRIMARY KEY (id)
- UNIQUE (user_id)
- GIN INDEX (specialties)
- GIN INDEX (areas)

**RLS:**
- 全員が営業代行一覧を閲覧可能
- 営業代行は自分のデータのみ更新可能
- 管理者は全て閲覧可能

### 4. matching_requests（マッチング申請）

| カラム名 | 型 | 制約 | 説明 |
|----------|-----|------|------|
| id | UUID | PK, DEFAULT gen_random_uuid() | 申請ID |
| company_id | UUID | FK → profiles(id), NOT NULL | 企業ユーザーID |
| sales_agency_id | UUID | FK → profiles(id), NOT NULL | 営業代行ユーザーID |
| status | TEXT | NOT NULL, CHECK, DEFAULT 'pending' | ステータス |
| monthly_budget | INTEGER | | 月予算（円） |
| request_detail | TEXT | NOT NULL | 依頼内容 |
| deadline | DATE | | 提案期限 |
| rejected_reason | TEXT | | 却下理由 |
| created_at | TIMESTAMPTZ | NOT NULL, DEFAULT NOW() | 作成日時 |
| updated_at | TIMESTAMPTZ | NOT NULL, DEFAULT NOW() | 更新日時 |

**CHECK制約:**
- status IN ('pending', 'approved', 'rejected')

**インデックス:**
- PRIMARY KEY (id)
- INDEX (company_id)
- INDEX (sales_agency_id)
- INDEX (status)
- INDEX (created_at DESC)

**RLS:**
- 企業は自分が作成した申請のみ閲覧可能
- 営業代行は自分宛の申請を閲覧・更新可能
- 管理者は全て閲覧可能

---

### 5. message_threads（メッセージスレッド）

| カラム名 | 型 | 制約 | 説明 |
|----------|-----|------|------|
| id | UUID | PK, DEFAULT gen_random_uuid() | スレッドID |
| company_id | UUID | FK → profiles(id), NOT NULL | 企業ユーザーID |
| sales_agency_id | UUID | FK → profiles(id), NOT NULL | 営業代行ユーザーID |
| matching_request_id | UUID | FK → matching_requests(id) | 元の申請ID |
| last_message_at | TIMESTAMPTZ | | 最終メッセージ日時 |
| company_unread_count | INTEGER | NOT NULL, DEFAULT 0 | 企業側未読件数 |
| sales_agency_unread_count | INTEGER | NOT NULL, DEFAULT 0 | 営業代行側未読件数 |
| created_at | TIMESTAMPTZ | NOT NULL, DEFAULT NOW() | 作成日時 |

**UNIQUE制約:**
- UNIQUE (company_id, sales_agency_id)

**インデックス:**
- PRIMARY KEY (id)
- INDEX (company_id)
- INDEX (sales_agency_id)
- INDEX (last_message_at DESC)

**RLS:**
- 企業は自分のスレッドのみ閲覧可能
- 営業代行は自分のスレッドのみ閲覧可能
- 管理者は全て閲覧可能

---

### 6. messages（メッセージ）

| カラム名 | 型 | 制約 | 説明 |
|----------|-----|------|------|
| id | UUID | PK, DEFAULT gen_random_uuid() | メッセージID |
| thread_id | UUID | FK → message_threads(id), NOT NULL | スレッドID |
| sender_id | UUID | FK → profiles(id), NOT NULL | 送信者ID |
| content | TEXT | NOT NULL | メッセージ内容 |
| is_read | BOOLEAN | NOT NULL, DEFAULT FALSE | 既読フラグ |
| created_at | TIMESTAMPTZ | NOT NULL, DEFAULT NOW() | 送信日時 |

**インデックス:**
- PRIMARY KEY (id)
- INDEX (thread_id, created_at DESC)
- INDEX (sender_id)

**RLS:**
- スレッドの参加者のみメッセージを閲覧可能
- スレッドの参加者のみメッセージを送信可能
- 管理者は全て閲覧可能

## 🔧 トリガー・関数

### 1. メッセージ送信時の未読カウント更新

```sql
CREATE OR REPLACE FUNCTION increment_unread_count()
RETURNS TRIGGER AS $$
BEGIN
  UPDATE message_threads
  SET 
    company_unread_count = CASE 
      WHEN NEW.sender_id != company_id THEN company_unread_count + 1
      ELSE company_unread_count
    END,
    sales_agency_unread_count = CASE 
      WHEN NEW.sender_id != sales_agency_id THEN sales_agency_unread_count + 1
      ELSE sales_agency_unread_count
    END,
    last_message_at = NEW.created_at
  WHERE id = NEW.thread_id;
  
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER message_insert_trigger
AFTER INSERT ON messages
FOR EACH ROW
EXECUTE FUNCTION increment_unread_count();
```

### 2. メッセージ既読時の未読カウント減少

```sql
CREATE OR REPLACE FUNCTION decrement_unread_count()
RETURNS TRIGGER AS $$
BEGIN
  IF NEW.is_read = TRUE AND OLD.is_read = FALSE THEN
    UPDATE message_threads
    SET 
      company_unread_count = CASE 
        WHEN NEW.sender_id != company_id THEN GREATEST(company_unread_count - 1, 0)
        ELSE company_unread_count
      END,
      sales_agency_unread_count = CASE 
        WHEN NEW.sender_id != sales_agency_id THEN GREATEST(sales_agency_unread_count - 1, 0)
        ELSE sales_agency_unread_count
      END
    WHERE id = NEW.thread_id;
  END IF;
  
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER message_read_trigger
AFTER UPDATE ON messages
FOR EACH ROW
EXECUTE FUNCTION decrement_unread_count();
```

### 3. マッチング承認時のスレッド自動作成

```sql
CREATE OR REPLACE FUNCTION create_thread_on_approval()
RETURNS TRIGGER AS $$
BEGIN
  IF NEW.status = 'approved' AND (OLD.status IS NULL OR OLD.status != 'approved') THEN
    INSERT INTO message_threads (
      company_id,
      sales_agency_id,
      matching_request_id
    )
    VALUES (
      NEW.company_id,
      NEW.sales_agency_id,
      NEW.id
    )
    ON CONFLICT (company_id, sales_agency_id) DO NOTHING;
  END IF;
  
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER matching_approval_trigger
AFTER UPDATE ON matching_requests
FOR EACH ROW
EXECUTE FUNCTION create_thread_on_approval();
```
