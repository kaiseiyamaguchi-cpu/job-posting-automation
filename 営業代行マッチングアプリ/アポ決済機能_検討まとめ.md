## 1. 要望の整理

### 1.1 前提

- 鬼カナ社が営業顧問と企業をマッチングするプラットフォーム
- **アポ型ビジネスモデル**: 営業顧問が企業に顧客を紹介し、商談が成立したら報酬が発生

### 1.2 ビジネスの流れ

```
営業顧問 → 顧客を紹介 → 企業
                          ↓
                    企業 ↔ 顧客（商談）
                          ↓
                    アポ成立（商談実施）
                          ↓
              企業が営業顧問にアポ費用支払い
                    （3~5万円）
                          ↓
                営業顧問80% / 鬼カナ20%
```

### 1.3 課題

- **アポが実施されたかの判定が難しい**
- 企業が支払いを拒否するリスク
- 営業顧問が証明することは困難

---

## 2. ビジネスフロー

### 2.1 確定フロー

```
【1】営業顧問が顧客を紹介
  - 顧客企業名、担当者情報、紹介理由を入力
  - アポ単価を提示（3~5万円の範囲）

【2】企業が受理 + 商談日時を確定
  - オンライン商談（Zoom/Google Meet等）前提
  - 日時を確定
  
【3】★ 決済発生
  - 企業のクレカから決済
  - 鬼カナのStripeアカウントに入金

【4】商談実施
  - 企業と顧客（紹介された会社）が商談
  - 営業顧問は同席しない

【5】商談終了後48時間の異議申立期間
  - デフォルト: 何もしなければ自動確定
  - 企業が「無効商談」を主張する場合のみ申立
  - 申立には証拠（録画、スクショ等）の提出が必要

【6】分配 or 返金
  - 異議なし → 自動確定
    → 営業顧問の残高に80%加算
    → 鬼カナに20%
  - 異議あり → 管理者が裁定
    → 有効: 上記と同じ
    → 無効: 全額返金
```

## 3. 決済タイミングと48時間ルール

### 3.1 事前決済の理由

**問題**: 後払いだと企業が支払わないリスクが高い

**解決策**: 商談日時確定時に決済を実行

**メリット**:
- ✅ 営業顧問が完全に保護される
- ✅ 未払いリスクゼロ
- ✅ 企業が真剣に商談に臨む動機

**デメリット**:
- ⚠️ 企業の心理的ハードルが高い
- ⚠️ 無効商談の判定が必要

### 3.2 48時間ルール

**仕組み**:
- 商談実施後48時間以内に企業が異議申立可能
- 異議がなければ自動確定
- 立証責任は企業側（無効を主張する側）

**有効アポの基準**:
1. 商談が実施された
2. 決裁権者または影響力のある人物が出席
3. 商談時間が一定以上（10分以上推奨）
4. 紹介情報が正確だった

**無効アポの例**:
- 顧客が現れなかった（ドタキャン）
- 5分で終了した
- 紹介情報が虚偽だった

### 3.3 証拠提出

**利用規約に明記**:
> 「無効な商談や、キャンセルがあった予防のために、管理者側からスクリーンショットや動画の録画を求める場合があります」

**実装**:
- 企業が異議申立時に証拠をアップロード
- 管理者が証拠を確認して裁定
- 必要に応じて営業顧問にも証拠提出を要求

## 4. 資金決済法の問題

### 4.1 資金移動業の該当性

**資金決済法 第2条第2項**:
> 「銀行等以外の者が為替取引を業として営むこと」が資金移動業

**本モデルでの該当性分析**:

| 要件 | 本モデル | 評価 |
|------|---------|------|
| 資金の移動 | 企業 → 営業顧問への資金移動 | ✅ 該当 |
| 隔地者間 | 企業と営業顧問は別の主体 | ✅ 該当 |
| 現金輸送によらない | 銀行振込・Stripe | ✅ 該当 |
| 依頼を受けて引き受ける | プラットフォームが仲介 | ✅ 該当 |
| 業として | 反復継続的に実施 | ✅ 該当 |
| 銀行等以外 | 鬼カナは銀行ではない | ✅ 該当 |

**結論**: **資金移動業に該当する可能性が極めて高い（95%以上）**

### 4.2 無登録の場合の罰則

**資金決済法 第107条**:
- **懲役3年 or 罰金300万円**（またはその併科）
- 業務停止命令
- 事業継続不可能

### 4.3 適用除外の可能性

#### 「代理受領権」による適用除外

**金融庁の解釈（2024年12月）**:
> 「プラットフォームが売主からの代理受領権に基づいて買主から代金を受領し、買主に二重払いの危険がない関係が成立する場合、資金移動業に該当しない可能性がある」

**要件**:
1. プラットフォームと営業顧問の間に代理受領契約
2. 企業が鬼カナに支払えば義務履行完了
3. 取引の成立・管理にプラットフォームが関与

**評価**: ⚠️ **グレーゾーン**
- 主張は可能だが100%安全ではない
- 金融庁の解釈次第
- 裁判になれば負ける可能性あり

### 4.4 取引規模別リスク

| 月間取引件数 | リスクレベル | 説明 |
|-------------|-------------|------|
| 1~5件 | 🟢 低 | 金融庁の目に留まりにくい |
| 10~30件 | 🟡 中 | グレーゾーン |
| 50件以上 | 🔴 高 | 摘発リスク大 |
| 100件以上 | 🔴 極めて高い | ほぼ確実に指摘 |

## 5. 税務処理の問題

### 5.1 消費税

#### パターンA: 総額を売上計上（鬼カナが取引主体）
```
売上: 50,000円（課税売上）
外注費: 40,000円
→ 消費税計算が複雑
→ 仕入税額控除の可否が不明確
```

#### パターンB: 手数料のみ売上計上（仲介者）
```
売上: 10,000円（手数料のみ、課税売上）
→ シンプル
→ Stripe Connectならこの形
```

**推奨**: パターンB

### 5.2 源泉徴収

**営業顧問への支払いが「外交員」に該当する可能性**:
- 該当する場合: 源泉徴収10.21%が必要
- 例: 40,000円 → 源泉徴収4,084円 → 手取り35,916円

**回避方法**:
1. 営業顧問を法人に限定（個人事業主は除外）
2. Stripe Connectで直接支払い（鬼カナは支払っていない）

**推奨**: 方法2（Stripe Connect）

### 5.3 プラットフォーム課税（2025年4月施行）

- 国外事業者が関与する場合に適用
- 本モデルは主に国内想定なので影響小

## 6. 実装の選択肢

### 6.1 選択肢A: 手動運用

#### 仕組み
```
企業 → Stripe決済 → 鬼カナのStripeアカウント（全額）
                    ↓
              鬼カナが手動で集計
                    ↓
              月末に銀行振込
```

#### メリット
- ✅ 開発工数: 最小（1週間）
- ✅ 初期コスト: ゼロ
- ✅ すぐに開始可能

#### デメリット
- ❌ **資金決済法のリスク極めて高い**
- ❌ 手動振込の運用コスト
- ❌ スケールしない

#### 評価
**⚠️ 小規模（月5件未満）で短期間（1~2ヶ月）のみ許容可能**

---

### 6.2 選択肢B: Stripe Connect Express（推奨）

#### 仕組み
```
【営業顧問登録時】
→ Stripe Connect Expressアカウントを作成
→ 営業顧問が銀行口座情報等を入力（5~10分）

【決済時】
→ Stripe Payment Intentを作成（未確定）
→ 48時間後に自動確定
→ Stripeが自動分配:
  - 営業顧問: 80%
  - 鬼カナ: 20%
```

#### メリット
- ✅ **資金決済法のリスクゼロ**
- ✅ 自動化、スケーラブル
- ✅ 税務処理がシンプル
- ✅ 源泉徴収義務なし

#### デメリット
- ❌ 営業顧問が5~10分の登録作業必要
- ❌ 登録完了率70~80%程度（20~30%が途中離脱）
- ❌ Stripe手数料: 3.6%
- ❌ 「翌月25日振込」の要件は満たせない
  - → 営業顧問が自由に出金タイミング設定

#### 開発工数
- 実装期間: 2~3週間
- 複雑度: 中

#### 評価
**✅ 中長期的にはこれがベスト**

---

#### メリット

#### デメリット

- ❌ 時間がかかる
- ❌ 継続コンプライアンスコスト

#### 評価

### 6.4 選択肢D: 代理受領スキーム + 手動運用

#### 仕組み
- 選択肢Aに法的対策を追加
- 利用規約に代理受領条項を明記

#### メリット

#### デメリット
- ❌ リスクは残る（30%）
- ❌ 弁護士費用: 30~50万円
- ❌ 月間5件未満に制限すべき

**△ リスクテイク派向け、短期限定**

### 7.2 Stripe Connect実装の概要

#### Step 1: 営業顧問登録
```typescript
// Stripe Connectアカウント作成
const account = await stripe.accounts.create({
  type: 'express',
  country: 'JP',
  email: agency.email,
});

// オンボーディングリンク生成
const accountLink = await stripe.accountLinks.create({
  account: account.id,
  type: 'account_onboarding',
  // ...
});
```

#### Step 2: 決済（未確定）
```typescript
// Payment Intent作成（confirm: false）
const paymentIntent = await stripe.paymentIntents.create({
  amount: 50000 * 100,
  currency: 'jpy',
  confirm: false,  // まだ確定しない
  application_fee_amount: 10000 * 100, // 20%
  transfer_data: {
    destination: agency.stripe_account_id,
  },
});
```

#### Step 3: 48時間後の自動確定
```typescript
// Payment Intentを確定
await stripe.paymentIntents.confirm(paymentIntent.id);
// → この瞬間に自動分配される
```

#### Step 4: 異議申立時はキャンセル
```typescript
await stripe.paymentIntents.cancel(paymentIntent.id);
// → 企業に全額返金
```

### 7.4 利用規約の重要条項

```markdown
## 第X条（アポイントメント料金の決済）

1. 企業が営業顧問からの顧客紹介を受理し、商談日時を確定した時点で、
   アポイントメント料金の決済が発生します。

2. 決済はクレジットカードによる即時決済とします。

3. 商談予定時刻の48時間後に、決済が自動的に確定されます。

4. 企業は、商談予定時刻の48時間以内に限り、以下の理由により
   「無効商談」として異議を申し立てることができます：
   
   a) 紹介された顧客が商談に出席しなかった
   b) 商談時間が著しく短時間（10分未満）で終了した
   c) 紹介された顧客情報が事前の説明と著しく異なっていた

5. 異議を申し立てる企業は、証拠（商談ログ、スクリーンショット、
   録画等）の提出を求められる場合があります。

6. 管理者は、双方に対し証拠の提出を求め、商談の有効性を判定します。

7. 商談の録画・録音を推奨します。ただし、事前に商談相手の同意を得るものとします。
```

**リスク:**
- 営業顧問の登録完了率が70~80%（20~30%が離脱）
- → 登録プロセスの最適化で軽減可能

**この方針で開発を進めることを強く推奨します。**
